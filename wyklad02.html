Architektura przeglądarki

Jak Przeglądarka Widzi Twój Kod: DOM vs Accessibility Tree

Kiedy przeglądarka pobiera plik HTML, buduje dwa równoległe drzewa danych:

1. Drzewo DOM (Document Object Model)

Struktura węzłów reprezentująca hierarchię znaczników w pamięci RAM, modyfikowana przez JavaScript i łączona z CSSOM w Render Tree.

2. Drzewo Dostępności (Accessibility Tree)

Wyspecjalizowane drzewo przekazywane bezpośrednio do API systemu operacyjnego (np. Windows UI Automation, macOS NSAccessibility) dla czytników ekranu (NVDA, VoiceOver).

Dlaczego <div> niszczy dostępność?

Kod HTMLRola w A11Y TreeNawigacja klawiaturą
<div class="btn">generic (brak)❌ Brak (wymaga TabIndex + JS)
<button>button (natywna)✅ Klawisze Tab, Enter, Spacja
<div class="menu">generic (brak)❌ Niewidoczne jako landmark
<nav>navigation (landmark)✅ Czytnik skacze skrótem klawiszowym
Używając semantycznego HTML5, dostajesz obsługę klawiatury, role i dostępność za darmo – bez ani jednej linii JavaScriptu!
Struktura dokumentu

Likwidacja „Div Soup” – Architektura Landmarków HTML5

Przeszłość: „Div Soup” (Antywzorzec)

<div id="header">
  <div class="logo">Portfel</div>
  <div class="nav-links">
    <a href="#">Start</a>
  </div>
</div>
<div id="content">
  <div class="post">...</div>
</div>
<div id="footer">© 2026</div>

Bot Google i czytnik ekranu widzą ciąg bezpłciowych bloków generic. Użytkownik niewidomy musi odsłuchać całą stronę od góry do dołu.

Teraźniejszość: Semantyczne Landmarki

<header>
  <h1>Portfel</h1>
  <nav aria-label="Główne">
    <ul><li><a href="#">Start</a></li></ul>
  </nav>
</header>
<main>
  <article>...</article>
</main>
<footer>© 2026</footer>
Żelazna zasada: Dokładnie jeden <main> na podstronę! Hierarchia nagłówków <h1> → <h2> → <h3> bez przeskoków poziomów.
Mikrosemantyka

Znaczniki Treści: Znaczenie Merytoryczne vs Czysty Wygląd

Precyzja Semantyczna

  • <strong> vs <b>: strong to ważne merytorycznie wyróżnienie (czytnik akcentuje głosem), b to tylko grubość czcionki bez znaczenia.
  • <em> vs <i>: em oznacza nacisk fonetyczny (emfazę), i to np. termin łaciński lub nazwa statku.
  • <figure> + <figcaption>: semantyczne powiązanie wykresu/zdjęcia z oficjalnym podpisem.
  • <time datetime="2026-10-09">: data czytelna dla człowieka i maszynowo parsowalna dla wyszukiwarek.

Specjalistyczne Tagi Tekstowe

<!-- Maszynowy czas publikacji -->
Opublikowano <time datetime="2026-10-09T15:00">
  9 października 2026
</time>

<!-- Obraz z podpisem -->
<figure>
  <img src="architektura.svg" alt="Diagram drzewa DOM">
  <figcaption>Rys. 1: Schemat renderowania silnika Blink</figcaption>
</figure>

<!-- Skrót klawiszowy dla użytkownika -->

Dostępność cyfrowa

Standard WCAG 2.2 – Cztery Zasady POUR

1. Postrzegalność (Perceivable)

Treść musi być dostępna dla wszystkich zmysłów. Teksty alternatywne dla grafik, napisy do wideo, kontrast tekstu minimum 4.5:1 (AA).

2. Funkcjonalność (Operable)

Każda akcja musi być wykonalna samą klawiaturą (Tab, Enter, Spacja). Widoczny wskaźnik skupienia (:focus-visible), brak pułapek klawiatury.

3. Zrozumiałość (Understandable)

Deklaracja <html lang="pl">, przewidywalna nawigacja, czytelne komunikaty błędów w formularzach wskazujące dokładnie które pole poprawić.

4. Kompatybilność (Robust)

Kod poprawny syntaktycznie wg specyfikacji W3C, poprawnie interpretowany przez przeglądarki, boty oraz technologie asystujące.

Dostępność to nie „dodatek dla garstki osób” – to wymóg prawny (Europejski Akt o Dostępności / EAA) oraz fundament profesjonalnej inżynierii webowej.
Media w HTML5

Sztuka Opisywania Obrazów: Kiedy i Jaki Atrybut alt?

1. Obraz Merytoryczny

Przekazuje kluczową treść artykułu:

<img src="wykres.png"
     alt="Wzrost ruchu mobilnego z 45% w 2020 do 68% w 2026">

Opisujemy to, co obraz przedstawia, a nie słowa „zdjęcie przedstawia”.

2. Obraz Funkcjonalny

Obraz będący linkiem lub przyciskiem:

<a href="/koszyk">
  <img src="cart.svg" 
       alt="Przejdź do koszyka (3 produkty)">
</a>

Opisujemy akcję, którą wywoła kliknięcie, a nie wygląd ikonki.

3. Obraz Czysto Dekoracyjny

Tło, plama koloru, ozdobnik:

<!-- Pusty alt lub aria-hidden -->
<img src="gwiazdka-tlo.svg" 
     alt="" 
     aria-hidden="true">

Brak atrybutu alt to błąd! Pusty alt="" mówi czytnikowi: „pomiń ten element”.

Standard ARIA

WAI-ARIA – Kiedy Stosować, a Kiedy Bezwzględnie Unikać?

Pierwsza Reguła ARIA (W3C):
„Jeśli możesz użyć natywnego elementu HTML5 o odpowiedniej semantyce, ZAWSZE go użyj, zamiast przekształcać inny element za pomocą ARIA.”

Zły kod (Bad ARIA):

<!-- Źle: symulacja przycisku na divie -->
<div role="button" tabindex="0" onclick="zapisz()">
  Zapisz dane
</div>

Wymaga ręcznego oprogramowania obsługi klawisza Enter i Spacja w JS!

Gdzie ARIA jest NIEZBĘDNA?

  • aria-expanded="false/true" – informacja dla czytnika czy menu hamburgerowe / akordeon jest rozwinięte.
  • aria-controls="menu-glowne" – powiązanie przycisku z identyfikatorem rozwijanego kontenera.
  • aria-live="polite" – dynamiczne powiadomienia (np. komunikat „Dodano produkt do koszyka” odczytany bez przeładowania strony).
  • aria-current="page" – wyróżnienie aktywnego linku w nawigacji.

Nowoczesne Pseudoklasy CSS do Formularzy

  • :focus-visible – ramka skupienia pojawia się tylko przy nawigacji klawiaturą, ukryta przy kliknięciu myszą!
  • :user-valid / :user-invalid – nowoczesne pseudoklasy (2025/2026). Pokazują błąd dopiero gdy użytkownik skończył edycję i opuścił pole.
/* Subtelny focus klawiaturowy */
input:focus-visible, button:focus-visible {
  outline: 3px solid #38bdf8;
  outline-offset: 2px;
}

/* Walidacja przyjazna dla użytkownika */
input:user-invalid {
  border-color: #fb7185;
}
input:user-valid {
  border-color: #34d399;
}
Architektura CSS

Nowa Kaskada w CSS: Warstwy @layer i Zero-Specificity

Tradycyjna kaskada często prowadziła do „wojen o specyficzność” i nadużywania !important. Nowoczesny CSS rozwiązuje to warstwami @layer:

/* Deklaracja kolejności priorytetów */
@layer reset, base, framework, components, utilities;

@layer reset {
  * { box-sizing: border-box; margin: 0; }
}

@layer components {
  .btn { background: #38bdf8; color: #000; }
}

@layer utilities {
  .d-none { display: none; }
}

Pseudoklasy :is() oraz :where()

:is() – grupuje selektory, przyjmuje wagę najcięższego ze składników.

:is(header, main, footer) a:hover {
  color: #38bdf8;
}

:where() – grupuje selektory, ale ma specyficzność zawsze równą 0! Idealne do bibliotek i stylów bazowych, które łatwo nadpisać.

:where(h1, h2, h3) {
  margin-block-end: 0.5em; /* Łatwe do nadpisania */
}
Rewolucja selektorów

Potęga Selektora :has() – tzw. „Parent Selector”

Przez 25 lat CSS nie potrafił ostylować rodzica na podstawie jego dzieci. Selektor :has() całkowicie to zmienił i eliminuje mnóstwo kodu JS!

Przykład 1: Karta z obrazem lub bez

/* Jeśli karta zawiera obraz, ułóż w 2 kolumny */
.card:has(img) {
  display: grid;
  grid-template-columns: 180px 1fr;
}

Przykład 2: Blokada scrolla przy otwartym oknie modalnym

/* Jeśli w body znajduje się otwarty dialog */
body:has(dialog[open]) {
  overflow: hidden;
}

Przykład 3: Dezaktywacja przycisku przy błędnym formularzu

form:has(input:invalid) button[type="submit"] {
  opacity: 0.5;
  pointer-events: none;
}
Układ 1D

Flexbox w Praktyce Inżynierskiej: Osie, Gap i Auto-Margins

Flexbox operuje na jednej osi: Main Axis (kierunek flex-direction) oraz Cross Axis.

Skrócona właściwość flex:

flex: <grow> <shrink> <basis>;

  • flex: 1 1 auto; → rozciągaj się i kurcz elastycznie.
  • flex: 0 0 280px; → sztywny pasek boczny o stałej szerokości.
Genialny trick: margin-left: auto wewnątrz kontenera Flexbox wypycha wybrany element (np. przycisk logowania lub avatar) maksymalnie do prawej krawędzi paska nawigacji! 
.navbar {
  display: flex;
  align-items: center;
  gap: 20px;
  padding: 12px 24px;
}

.nav-logo {
  font-weight: 700;
}

.nav-links {
  display: flex;
  gap: 16px;
  list-style: none;
}

/* Wypchnij profil użytkownika na sam koniec paska */
.nav-user-profile {
  margin-left: auto;
}
Układ 2D

CSS Grid – Dwu-Wymiarowa Inżynieria Układu

CSS Grid kontroluje wiersze i kolumny jednocześnie. Prawdziwa rewolucja to responsywna siatka bez pisania media queries:

.gallery-grid {
  display: grid;
  /* Kluczowa formuła inżynierska */
  grid-template-columns: 
    repeat(auto-fit, minmax(280px, 1fr));
  gap: 20px;
}
auto-fit vs auto-fill:
• auto-fit rozszerza istniejące karty, by wypełniły cały rząd.
• auto-fill zachowuje rozmiar kart i zostawia puste kolumny.

Układ Główny za Pomocą Grid Areas

.page-layout {
  display: grid;
  grid-template-areas:
    "naglowek  naglowek"
    "tresc     sidebar"
    "stopka    stopka";
  grid-template-columns: 1fr 300px;
  grid-template-rows: auto 1fr auto;
  min-height: 100vh;
}

header { grid-area: naglowek; }
main   { grid-area: tresc; }
aside  { grid-area: sidebar; }
footer { grid-area: stopka; }
Nowość CSS Grid

CSS Subgrid – Idealne Wyrównanie w Zagnieżdżonych Kartach

Odwieczny problem webmastera: Trzy karty w rzędzie. Jedna ma tytuł na 1 linijkę, druga na 3 linijki. W efekcie przyciski "Kup teraz" na dole kart są na różnych wysokościach!

Bez Subgrid:

Wewnętrzne elementy kart nie wiedzą nic o sąsiednich kartach. Układ jest poszarpany.

Z Subgrid:

Karta dzieli wiersze nadrzędnej siatki. Wszystkie tytuły, opisy i przyciski w całym rzędzie wyrównują się do wspólnych poziomych linii.

/* Kontener główny kart */
.cards-container {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 20px;
}

/* Karta rozciąga się na 3 wiersze siatki */
.card-item {
  grid-row: span 3;
  display: grid;
  /* Przejmij linie wierszy od rodzica! */
  grid-template-rows: subgrid;
}

.card-item h3 { /* wiersz 1 */ }
.card-item p  { /* wiersz 2 */ }
.card-item a  { /* wiersz 3 - idealnie równo! */ }
Płynny design

Matematyka CSS: Płynna Typografia z Funkcją clamp()

Zamiast tworzyć 6 reguł @media ze sztywnymi rozmiarami czcionek, definiujemy płynny zakres matematyczny:

Składnia funkcji clamp:

clamp(MIN, PREFEROWANA, MAX)

  • MIN: Minimalna wartość (np. na małym smartfonie).
  • PREFEROWANA: Wartość oparta o viewport (np. 2vw + 1rem).
  • MAX: Maksymalny limit (np. na monitorze 4K).
/* Płynny nagłówek h1 (od 28px do 56px) */
h1 {
  font-size: clamp(1.75rem, 4vw + 1rem, 3.5rem);
  line-height: 1.15;
}

/* Płynne marginesy i paddingi kontenera */
.container {
  width: min(92vw, 1280px);
  margin-inline: auto;
  padding: clamp(1rem, 3vw, 3.5rem);
}

/* Płynny odstęp między sekcjami */
section {
  padding-block: clamp(2rem, 6vw, 6rem);
}
Nowość CSS

Container Queries (@container) – Komponenty Nowej Generacji

Ograniczenie Media Queries: @media sprawdza wyłącznie szerokość całego ekranu. Nie wie, czy komponent znajduje się w wąskim sidebarze, czy na szerokiej stronie głównej.

Rozwiązanie: Kontener zapytania

Komponent bada szerokość swojego bezpośredniego rodzica i samodzielnie decyduje o swoim wyglądzie!

/* 1. Oznacz rodzica jako kontener pomiarowy */
.sidebar, .main-content {
  container-type: inline-size;
  container-name: card-slot;
}

/* 2. Domyślny wygląd karty (wąska - lista) */
.product-card {
  display: flex;
  flex-direction: column;
}

/* 3. Jeśli kontener ma min 500px, ułóż w poziomie! */
@container card-slot (min-width: 500px) {
  .product-card {
    flex-direction: row;
    align-items: center;
  }
}
Motywy i barwy

Zmienne CSS, Przestrzeń OKLCH i Architektura Dark Mode

Nowoczesny system kolorów opieramy o CSS Custom Properties oraz percepcję barw OKLCH (równomierna jasność dla ludzkiego oka):

:root {
  /* Przestrzeń oklch(jasnosc chroma odcien) */
  --bg-primary: oklch(0.98 0.01 240);
  --text-primary: oklch(0.15 0.02 240);
  --accent: oklch(0.65 0.22 230);
  color-scheme: light dark;
}

/* Automatyczny tryb ciemny z systemu */
@media (prefers-color-scheme: dark) {
  :root {
    --bg-primary: oklch(0.12 0.02 240);
    --text-primary: oklch(0.95 0.01 240);
    --accent: oklch(0.75 0.18 210);
  }
}

Przełącznik Motywu z Poziomu HTML

/* Nadpisanie z poziomu atrybutu data-theme */
[data-theme="dark"] {
  --bg-primary: oklch(0.12 0.02 240);
  --text-primary: oklch(0.95 0.01 240);
}
[data-theme="light"] {
  --bg-primary: oklch(0.98 0.01 240);
  --text-primary: oklch(0.15 0.02 240);
}

body {
  background-color: var(--bg-primary);
  color: var(--text-primary);
  transition: background-color 0.3s ease;
}

color-scheme: light dark sprawia, że suwaki przeglądarki i kontrolki formularzy same przełączają się w tryb ciemny!

Wydajność inżynierska

Cykl Renderowania Przeglądarki – Dlaczego Animujemy Tylko na GPU?

1. Layout (Reflow) ❌

Przeliczenie geometrii wszystkich elementów na stronie.

Zabójcy wydajności: animowanie width, height, top, left, margin, padding. Powoduje zacięcia (jank) na mobile!

2. Paint (Repaint) ⚠️

Rysowanie pikseli (kolory, cienie, tła) do warstw rastrowych.

Wymuszane przez zmiany background-color, color, box-shadow, border-color.

3. Composite (GPU) ✅

Składanie gotowych warstw na karcie graficznej.

Złoty standard: animujemy wyłącznie transform oraz opacity. Gwarancja 60/120 FPS!

Nigdy nie przesuwaj elementu właściwością left: 100px – zawsze używaj transform: translateX(100px)!
Animacje CSS

Płynne Mikrointerakcje & Nowości CSS (@starting-style)

Interaktywna Karta na GPU

.interactive-card {
  background: rgba(18, 24, 38, 0.8);
  border-radius: 12px;
  border: 1px solid rgba(255,255,255,0.08);
  /* Animacja właściwości kompozytora */
  transition: transform 0.25s cubic-bezier(0.2, 0.8, 0.2, 1),
              box-shadow 0.25s ease;
  will-change: transform;
}

.interactive-card:hover {
  transform: translateY(-6px) scale(1.015);
  box-shadow: 0 16px 32px rgba(0, 0, 0, 0.45);
}

Nowość: @starting-style (Animacja display: none)

/* Element pojawiający się z display: none */
dialog[open] {
  opacity: 1;
  transform: scale(1);
  transition: opacity 0.3s ease, 
              transform 0.3s ease, 
              display 0.3s allow-discrete;
}

/* Stan początkowy w momencie wejścia */
@starting-style {
  dialog[open] {
    opacity: 0;
    transform: scale(0.92);
  }
}
