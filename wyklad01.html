Fundament #1

HTML: Język Struktury Dokumentu WWW

HTML (HyperText Markup Language) to kręgosłup każdej strony. Składa się z komend ujętych w nawiasy ostre <znacznik>:

  • <html lang="pl-PL"> – deklaracja języka i początek dokumentu.
  • <head> – sekcja nagłówkowa (metadane, tytuł, style, skrypty – niewidoczne bezpośrednio na stronie).
  • <title> – tytuł karty w oknie przeglądarki.
  • <body> – ciało strony zawierające całą widoczną treść dokumentu.
<!DOCTYPE html>
<html lang="pl-PL">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Tytuł mojej strony</title>
  </head>
  <body>
    <h1>Witaj na mojej stronie!</h1>
    <p>To jest treść pierwszego dokumentu.</p>
  </body>
</html>
Formatowanie tekstu

Podstawy Formatowania Tekstu w HTML

Znaczniki Treści

  • <h1> do <h6> – nagłówki hierarchiczne dokumentu.
  • <p> – akapit tekstu (podstawa czytelności).
  • <br> – wymuszenie nowego wiersza (bez zamykania).
  • <strong> – ważne wyróżnienie pogrubione (dawniej <b>).
  • <em> – akcent / kursywa (dawniej <i>).
  • <s> lub <del> – tekst przekreślony.
  • <sup> i <sub> – indeks górny (np. m2) i dolny (np. H2O).

Media i struktury

Obrazy, Listy i Tabele w Praktyce

Obrazy (<img>)

Znacznik samozamykający z kluczowymi atrybutami:

<img src="foto.webp" 
     alt="Opis zdjęcia" 
     width="600" 
     height="400">

Atrybut alt jest bezwzględnie wymagany ze względów dostępności (WCAG) i SEO!

Listy (<ul> i <ol>)

Wypunktowane (unordered) i numerowane (ordered):

<ul>
  <li>WordPress</li>
  <li>Joomla</li>
  <li>Ghost CMS</li>
</ul>

Menu nawigacyjne na stronach budujemy niemal zawsze na bazie listy <ul>.

Tabele (<table>)

Służą wyłącznie do danych zestawieniowych:

<table>
  <tr>
    <th>CMS</th><th>Silnik</th>
  </tr>
  <tr>
    <td>Ghost</td><td>Node.js</td>
  </tr>
</table>

⚠️ Nigdy nie używamy tabel do pozycjonowania layoutu strony!

Hipertekst

Odnośniki (<a href="...">) – Istota Sieci WWW

Rodzaje Linków

  • Do innej strony:
    <a href="https://ideis.pl">Portal Uczelni</a>
  • Otwieranie w nowej karcie:
    <a href="https://..." target="_blank" rel="noopener">Nowa karta</a>
  • Pobieranie pliku (ZIP/PDF):
    <a href="materialy.zip" download>Pobierz archiwum</a>
  • Wysyłka e-mail (mailto):
    <a href="mailto:nauczanie@pm.me">Napisz do mnie</a>
  • Kotwica na tej samej stronie:
    <a href="#kontakt">Skocz do kontaktu</a>

Dobre Praktyki Bezpieczeństwa Linków

Zawsze przy użyciu target="_blank" dopisujemy rel="noopener noreferrer" – zapobiega to atakowi typu tabnabbing (przejęciu okna nadrzędnego przez otwartą kartę).

Treść odnośnika musi być zrozumiała bez czytania otoczenia. Unikaj tekstów typu "kliknij tutaj" – zamiast tego użyj: "Pobierz sylabus przedmiotu w formacie PDF".

Fundament #2

CSS (Cascading Style Sheets) – Oddzielenie Wyglądu od Treści

Kaskadowe Arkusze Stylów odpowiadają za całą warstwę wizualną: kolory, typografię, odstępy, układ i animacje.

Trzy Filary Kaskadowości:

  1. Hierarchia źródeł: Style inline > Styl w tagu <style> > Zewnętrzny plik .css.
  2. Specyficzność selektora: ID (100) > Klasa (10) > Element (1).
  3. Kolejność zapisu: W razie równej wagi wygrywa reguła zdefiniowana niżej w kodzie.
/* Anatomia reguły CSS */
selektor {
  wlasciwosc: wartosc;
}

/* Przykład */
h1 {
  color: #38bdf8;
  font-size: 2.5rem;
  letter-spacing: -0.02em;
}

.karta-produktu {
  background-color: #0f172a;
  border-radius: 12px;
  padding: 20px;
}

Układ strony

Pozycjonowanie Elementów: Flexbox vs CSS Grid

Flexbox (Układ 1D)

Idealny do pasków nawigacji, wyrównywania elementów w wierszu lub kolumnie:

.flex-container {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: 15px;
}

Elementy elastycznie kurczą się i rozciągają wzdłuż jednej osi głównej.

CSS Grid (Układ 2D)

Idealny do struktury całych podstron i responsywnych siatek kart:

.grid-container {
  display: grid;
  grid-template-columns: 
    repeat(auto-fit, minmax(280px, 1fr));
  gap: 20px;
}

Siatka automatycznie dostosowuje liczbę kolumn do szerokości ekranu bez media queries!

Dynamika wizualna

Efekty Przejścia i Płynne Animacje w CSS

Współczesna strona internetowa reaguje na akcje użytkownika mikrointerakcjami. Robimy to czystym CSS bez konieczności używania JavaScriptu!

Złota zasada animacji (GPU):

Animujemy wyłącznie transform oraz opacity. Przeglądarka przekazuje te obliczenia karcie graficznej, gwarantując stałe 60 FPS na smartfonach. 

/* Płynny przycisk z efektem uniesienia */
.karta-artykulu {
  background: #1e293b;
  border-radius: 8px;
  /* Kluczowa reguła płynności */
  transition: transform 0.3s ease, 
              box-shadow 0.3s ease;
}

/* Reakcja na najechanie kursorerm */
.karta-artykulu:hover {
  transform: translateY(-6px) scale(1.02);
  box-shadow: 0 12px 25px rgba(0,0,0,0.4);
}
Punkt Zwrotny Wykładu

A Jakby Podejść do Tematu Całkowicie Inaczej?

Napisanie strony w HTML i CSS to świetna lekcja inżynierii, ale wyobraźmy sobie klienta, który codziennie publikuje 5 wpisów blogowych, zmienia ceny w cenniku i dodaje zdjęcia...

Czysty Kod (Sam HTML & CSS):

  • Każda literówka wymaga edycji pliku i ponownego wdrożenia.
  • Klient musi znać składnię tagów HTML i bać się, że "zepsuje layout".
  • Brak bazy danych, wyszukiwarki, ról użytkowników.

System CMS (Content Management):

  • Edycja w przeglądarce w intuicyjnym edytorze (Wysiwyg / Markdown).
  • Pełna separacja treści od szaty graficznej.
  • Klient zarządza mediami, my dbamy o infrastrukturę.
Zarządzanie treścią

Co to Jest CMS i Jakie Funkcje Zapewnia?

CMS (Content Management System) to aplikacja internetowa umożliwiająca tworzenie, modyfikację i organizację treści cyfrowych bez konieczności bezpośredniej edycji kodu źródłowego witryny.

Kluczowe Zadania Systemu CMS:

  • Proste dodawanie artykułów, stron i produktów.
  • Zarządzanie biblioteką mediów (zdjęcia, filmy, dokumenty).
  • System ról i uprawnień (Autor, Redaktor, Administrator).
  • Silnik szablonów decydujący o wyglądzie strony.
  • Rozszerzalność za pomocą wtyczek / modułów / API.

Open Source vs Zamknięty SaaS

Open Source (Nasz wybór):

  • Pełny dostęp do kodu źródłowego, brak opłat licencyjnych.
  • Możliwość instalacji na własnym serwerze (Linux / kontener).
  • WordPress, Joomla, Ghost CMS.

Zamknięty SaaS (Wix, Squarespace, Shopify):

  • Szybki start, ale wysokie abonamenty i uzależnienie od platformy (vendor lock-in).
Filary semestru

Wielka Trójka CMS w Naszym Programie

W tym semestrze przetestujemy trzy zupełnie różne filozofie podejścia do zarządzania treścią.

Rynkowy Gigant

WordPress

~40% globalnego internetu. Najpopularniejszy, olbrzymi ekosystem. Dowiemy się dlaczego bywa krytykowany ("ble") i jak używać go profesjonalnie (Gutenberg, Headless REST API).

Struktura & ACL

Joomla 5

Potęga ról i uprawnień. Wielojęzyczność z pudełka, inżynierski model MVC, wielopoziomowe uprawnienia ACL. Niezastąpiona w portalach publicznych i intranetach.

Nowoczesność

Ghost CMS

Nowa era: Node.js & Markdown. Ekstremalna szybkość, czyste Content API, wbudowane subskrypcje dla czytelników i genialny edytor treści. Ulubieniec deweloperów.

CMS #1

WordPress – Dlaczego "Ble", a Dlaczego Musimy Go Znać?

Ciemna strona ("ble"):

  • Piekło wtyczek (Plugin Hell): Instalowanie 40 wtyczek spowalnia stronę i generuje konflikty.
  • Główny cel botów: 95% włamań wynika z nieaktualnych, dziurawych wtyczek firm trzecich.
  • Ociężałe page-buildery: Narzędzia wizualne generujące gigantyczny, nieoptymalny kod HTML.

Podejście inżynierskie (2026/27):

  • Edytor Gutenberg & FSE: Korzystanie z natywnych bloków bez zewnętrznych kombajnów.
  • Headless WordPress: WordPress jako bezpieczny panel redakcyjny wystawiający dane przez WP REST API.
  • Hardening: Wyłączenie XML-RPC, ochrona panelu i stałe aktualizacje.
CMS #2

Joomla 5 – Inżynierski Porządek i Architektura Uprawnień

Joomla to platforma wybierana tam, gdzie WordPress okazuje się zbyt chaotyczny pod kątem praw dostępu.

Mocne strony architektury Joomli:

  • Zaawansowane ACL: Dowolnie zagnieżdżane grupy użytkowników z precyzyjnymi prawami do podglądu, edycji i publikacji.
  • Natywna wielojęzyczność: Obsługa wielu wersji językowych bez konieczności płatnych wtyczek.
  • Wzorzec MVC: Czysty podział na Model, Widok i Kontroler w komponentach.

Gdzie spotkasz Joomlę?

  • Uczelnie wyższe i instytucje edukacyjne.
  • Serwisy samorządowe i administracji publicznej (BIP).
  • Intranety korporacyjne z podziałem na działy firmy.
Joomla wymaga więcej nauki na starcie, ale zapewnia znakomitą strukturę danych.
CMS #3 (Nowość)

Ghost CMS – Minimalizm, Node.js i Czysty Markdown

Ghost powstał jako bezpośrednia odpowiedź na przekombinowanie WordPressa. Jego celem jest jedna rzecz: doskonała publikacja treści.

Dlaczego deweloperzy uwielbiają Ghosta?

  • Architektura Node.js: Błyskawiczne czasy odpowiedzi i małe zużycie zasobów.
  • Edytor Markdown & Kart: Pisanie treści z formatowaniem kodu bez rozpraszaczy.
  • Natywne Content API: Ghost działa idealnie jako Headless CMS dla każdego frontendu.
  • Newsletter & Memberships: Wbudowany system subskrypcji czytelników z pudełka.
// Pobranie danych z Ghost Content API:
import GhostContentAPI from '@tryghost/content-api';

const api = new GhostContentAPI({
  url: 'http://localhost:2368',
  key: '22444f78447824223ce6a7c059',
  version: "v5.0"
});

// Pobieramy wpisy jako czysty JSON:
const posts = await api.posts.browse({ limit: 5 });

Most do przyszłości

Wprowadzenie do Frameworków i Astro

Świat Frameworków JS (React itp.)

React dominuje w ilości pobrań plików frontendowych. Budujemy aplikacje z gotowych klocków komponentowych. Ale czy każda strona potrzebuje ciężkiego runtime'u JS?

Astro: Architektura Wysp (Islands)

Astro kompiluje kod do czystego HTML i CSS (Zero JS by default). Skrypt JavaScript jest ładowany tylko dla tych elementów, które rzeczywiście są interaktywne.

W tym semestrze połączymy świat CMS ze światem nowoczesnych frameworków – np. pobierając treści z Ghosta lub WordPressa do ultraszybkiego serwisu w Astro!
