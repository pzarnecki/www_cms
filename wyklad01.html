Jak uczono tworzenia stron 15 lat temu?

  • Piszemy HTML w Notatniku lub Pajączku bez żadnego lintera.
  • Style wrzucane inline lub tabele służące do pozycjonowania layoutu (<table>).
  • Wgrywanie plików ręcznie przez FileZilla / Total Commander bezpośrednio do /public_html.
  • Brak kontroli wersji: pliki index_final_v2_naprawione.html.
  • WordPress instalowany na tanim hostingu współdzielonym bez kopii zapasowych, podatny na boty.

Standard inżynierski w 2026/2027:

  • Semantyczny HTML5 & CSS Modern: CSS Grid, Flexbox, custom properties, dostępność (WCAG/a11y).
  • Wersjonowanie: Git jako jedyne źródło prawdy (Single Source of Truth).
  • CI/CD i Hosting Edge: Automatyczny deploy z git push na GitHub Pages lub Cloudflare Pages.
  • Infrastruktura: Kontenery Podman/Docker, serwery Linux (Ubuntu/Debian), reverse proxy (Caddy/Nginx) z auto-SSL.
  • CMS: Architektura Headless, API-first (Ghost, Astro, headless WP).

Odebranie strumienia HTML

HTTP/1.1 vs HTTP/2 vs HTTP/3

HTTP/1.1: Jedno żądanie na połączenie (head-of-line blocking). Wymagało łączenia skryptów w jeden plik.

HTTP/2: Multipleksowanie połączeń na jednym gnieździe TCP.

HTTP/3 (QUIC): Oparte na protokole UDP! Zero blokowania przy utracie pakietów, błyskawiczny handshake.

DNS & Rekordy domenowe

A / AAAA: Wskazują adres IPv4 / IPv6 hosta.

CNAME: Alias do innej nazwy domenowej (używane np. w GitHub Pages i Cloudflare Pages).

TXT: Weryfikacja własności, SPF, DKIM.

Bezpieczeństwo: HTTPS & TLS

W 2026 r. brak HTTPS oznacza odrzucenie przez przeglądarki i spadek w SEO.

Certyfikaty Let's Encrypt i automatyzacja w serwerach takich jak Caddy zdejmują z nas manualną pracę.

Jak myśli przeglądarka

Krytyczna Ścieżka Renderowania (Critical Rendering Path)

Przeglądarka nie jest zwykłym wyświetlaczem tekstu – to potężny silnik kompilacji i kompozycji graficznej.

Krok po kroku: Silnik Blink / Gecko

  1. Parsowanie HTML → Drzewo DOM (Document Object Model). Każdy tag staje się węzłem w pamięci.
  2. Parsowanie CSS → Drzewo CSSOM (CSS Object Model). Przeglądarka liczy kaskadę stylów.
  3. Łączenie → Drzewo Renderowania (Render Tree): Zawiera tylko widoczne elementy (pomija display: none).
  4. Układ (Layout / Reflow): Wyliczanie geometrii każdego elementu (szerokość, współrzędne X/Y).
  5. Rysowanie (Paint): Wypełnianie pikseli (kolory, tła, cienie).
  6. Kompozycja (Composite): Składanie warstw przez procesor karty graficznej (GPU).

Wskazówka wydajnościowa dla inżyniera:

Dlaczego to ma znaczenie?
Zmiana właściwości takich jak width, margin czy top wymusza ponowny Layout i Paint dla całego drzewa (spadek FPS na smartfonach).

Animacje wykonujemy wyłącznie na właściwościach kompozytora GPU:

/* ZŁE - wymusza kosztowny Reflow */
.box:hover { left: 50px; width: 200px; }

/* DOBRE - operuje na GPU (Composite only) */
.box:hover { transform: translateX(50px) scale(1.1); }

Semantyczny HTML5: Dlaczego <div> to ostateczność?

Strona www to nie tylko kolorowy obrazek na monitorze. Czytają ją:

  • Czytniki ekranu osób z niepełnosprawnościami (Screen Readers - NVDA, VoiceOver).
  • Roboty wyszukiwarek (Googlebot, Bingbot) indeksujące treść dla SEO.
  • Tryby czytania w przeglądarkach (Safari Reader, Firefox Reader Mode).
Złota reguła: Używaj znacznika o najściślejszym znaczeniu semantycznym. Jeśli to przycisk – użyj <button>, a nie <div onclick="...">!

Nowa era CSS

Współczesny CSS: Siła prostoty bez zbędnych frameworków

1. Flexbox vs CSS Grid

Flexbox: Układ 1-wymiarowy (wiersz LUB kolumna). Idealny do nawigacji, pasków narzędzi i wyśrodkowania elementów.

CSS Grid: Układ 2-wymiarowy (wiersze ORAZ kolumny jednocześnie). Król układu całych podstron i galerii.

/* Święty Graal responsywnego grida: */
.grid {
  display: grid;
  grid-template-columns: 
    repeat(auto-fit, minmax(280px, 1fr));
  gap: 1.5rem;
}

2. Zmienne (Custom Properties)

Natywny system motywów, dynamiczna zmiana kolorów w locie i brak potrzeby preprocesorów (Sass/Less) dla prostych projektów.

:root {
  --primary: #38bdf8;
  --bg: #0f172a;
}

[data-theme="light"] {
  --primary: #0284c7;
  --bg: #ffffff;
}

button {
  background-color: var(--primary);
}

3. Płynna typografia & :has()

Funkcja clamp() pozwala zapomnieć o setkach reguł @media dla każdego rozmiaru ekranu.

/* Płynny nagłówek min 24px, max 48px */
h1 {
  font-size: clamp(1.5rem, 4vw, 3rem);
}

/* Selektor rodzica :has() - rewolucja! */
figure:has(figcaption) {
  border: 1px solid #e2e8f0;
}
Architektura wdrożeń

Hosting Nowej Generacji: GitHub Pages & Cloudflare Pages

Dlaczego w 2026 roku nie płacimy za hosting dla statycznych stron i portfolio?

GitHub Pages

  • Wbudowany bezpośrednio w repozytorium kodu.
  • Darmowy hosting z automatycznym certyfikatem HTTPS (Let's Encrypt).
  • Wdrożenie z gałęzi main lub przez GitHub Actions.
  • Własna domena z obsługą DNS (CNAME).
  • Idealny dla: dokumentacji, prac laboratoryjnych, prezentacji tego wykładu!

Cloudflare Pages

  • Globalna sieć Anycast CDN w ponad 300 miastach na świecie (w tym Warszawa).
  • Czasy odpowiedzi rzędu < 20ms dla użytkowników na całym globie.
  • Wbudowane funkcje Edge Workers (kawałki kodu JavaScript wykonywane na brzegu sieci).
  • Nielimitowany darmowy transfer danych!
  • Wsparcie dla automatycznego budowania projektów Astro, React, Vite.
Na naszych laboratoriach: Każdy student opanuje wdrożenie strony z poziomu terminala i gita na platformy GitHub Pages oraz Cloudflare Pages.
Infrastruktura własna

Serwery Linux, Podman & Docker – Gdy potrzebujemy backendu i baz

Co zrobić, gdy strona wymaga bazy danych (MySQL, PostgreSQL) lub interpretera PHP / Node.js?

Własny Linux (VPS)

Tani serwer VPS (np. Hetzner, OVH, DigitalOcean za 15-20 zł/mc) daje pełną wolność i kontrolę root.

System operacyjny: Debian lub Ubuntu LTS – stabilność i bezpieczeństwo.

Podman / Docker

Nie instalujemy PHP i MySQL bezpośrednio w systemie! Zamykamy aplikacje w izolowanych kontenerach.

Podman: Bezpieczniejszy odpowiednik Dockera (daemonless, rootless out-of-the-box).

Wszystko definiowane w plikach compose.yaml.

Reverse Proxy (Caddy / Nginx)

Serwer przyjmujący ruch na porcie 80 i 443, kierujący go do odpowiednich kontenerów.

Caddy: Automatycznie pobiera i odnawia certyfikaty SSL z Let's Encrypt bez konfiguracji certbota!

Systemy Zarządzania Treścią

Czym jest CMS i dlaczego podbił Internet?

CMS (Content Management System) to oprogramowanie umożliwiające tworzenie, edycję, organizację i publikację treści cyfrowych bez konieczności bezpośredniej edycji kodu źródłowego strony przez autora.

Kluczowe moduły klasycznego CMS:

  • Warstwa danych: Relacyjna baza danych (MySQL/MariaDB, PostgreSQL) lub pliki Flat-File / Markdown.
  • Panel administracyjny (Back-office): Logowanie, zarządzanie użytkownikami, edytory WYSIWYG / Markdown.
  • Warstwa prezentacji (Front-end): Silnik szablonów renderujący HTML dla odwiedzających.
  • System wtyczek / rozszerzeń: Możliwość dobudowywania funkcjonalności (e-commerce, formularze, SEO).

Architektura tradycyjna (Monolit)

Baza danych, logika biznesowa i widok HTML są ściśle splecione w jednym procesie serwerowym.

[Baza Danych] ↔ [PHP / Logika] ↔ [Szablon HTML] → Użytkownik

Architektura nowoczesna (Headless CMS)

CMS zarządza TYLKO treścią i udostępnia ją jako REST API lub GraphQL. Frontend tworzymy w dowolnej technologii (Astro, React, czysty HTML).

[Headless CMS] → JSON API → [Astro / Szybki CDN] → Użytkownik

Rynkowy Gigant

WordPress

~40% globalnego internetu. Klasyczny monolit PHP/MySQL, wszechobecny na rynku pracy. Sprawdzimy dlaczego budzi skrajne emocje ("ble") i jak użyć go profesjonalnie w trybie Headless.

Struktura & ACL

Joomla

Potęga ról i uprawnień. Wielojęzyczność z pudełka, zaawansowane grupy uprawnień (ACL), czystszy podział MVC niż w WordPressie. Niezastąpiona w portalach publicznych i intranetach.

Nowoczesność

Ghost CMS

Świeży powiew: Node.js & Markdown. Niezrównana szybkość, czyste API, genialny edytor treści, wbudowane subskrypcje i newslettery. Nowy król dla twórców, blogerów i zespołów dev.

CMS #1

WordPress – Dlaczego "ble", a dlaczego musimy go znać?

Ciemna strona WordPressa ("ble"):

  • Piekło wtyczek (Plugin Hell): Instalacja 40 wtyczek spowalnia stronę do zera i generuje konflikty.
  • Luki bezpieczeństwa: Najpopularniejszy cel ataków botów na świecie (nieaktualne wtyczki to 95% wektorów włamań).
  • Dług technologiczny: Dziedzictwo architektury sprzed ponad 20 lat (struktura tabel wp_options i wp_postmeta).
  • Ociężałe page-buildery: Elementor i Divi potrafią generować 30 zagnieżdżonych divów dla jednego przycisku.

Jak robić to jak inżynier (2026/27):

  • Lekkie szablony blokowe: Natywny edytor Gutenberg i Full Site Editing (FSE) bez zewnętrznych kobył.
  • Headless WordPress: WordPress służy wyłącznie jako panel wprowadzania treści. Dane pobieramy przez WP REST API do frontendu w Astro.
  • Twarde zabezpieczenia: Wyłączenie XML-RPC, dwuskładnikowe logowanie (2FA), restrykcyjne nagłówki bezpieczeństwa i konteneryzacja.
  • Rynkowa prawda: Klienci pytają o WordPressa w 7 na 10 zleceń komercyjnych.
CMS #2

Joomla – Niewykorzystany potencjał korporacyjny

Podczas gdy uwaga marketingu skupia się na WordPressie, Joomla 5 rozwija się jako wyjątkowo solidne, inżynierskie środowisko do złożonych portali.

Mocne strony architektury Joomli:

  • Zaawansowany system ACL: Wielopoziomowe uprawnienia do edycji, publikacji i widoczności każdej pojedynczej kategorii czy modułu.
  • Wielojęzyczność (Multilingual): Wbudowana natywnie bez konieczności płatnych wtyczek (w przeciwieństwie do WPML w WordPressie).
  • Własne pola (Custom Fields): Tworzenie ustrukturyzowanych danych bez zewnętrznych dodatków.
  • Brak monolitycznego narzutu: Czysty wzorzec MVC (Model-View-Controller) w komponentach.

Kiedy wybieramy Joomlę?

  • Portale uczelniane, urzędowe, instytucje publiczne (BIP).
  • Intranety firmowe z podziałem na działy: księgowość, HR, zarząd, magazyn.
  • Serwisy wymagające publikacji w 4 różnych językach od pierwszego dnia.
Podsumowanie: Joomla ma wyższy próg wejścia niż WordPress, ale nagradza znacznie większym porządkiem architektonicznym przy złożonych projektach.
CMS #3 (Nasza Gwiazda)

Ghost CMS – Minimalizm, Szybkość i Node.js

Ghost powstał na Kickstarterze z jasną misją: stworzyć platformę wyłącznie do publikacji treści, która nie powtórzy błędów ociężałego WordPressa.

Dlaczego deweloperzy uwielbiają Ghosta?

  • Stos technologiczny: Node.js, Express, MySQL / SQLite, silnik szablonów Handlebars.
  • Ekstremalna szybkość: Średni czas generowania strony to ułamek sekundy (nawet 19x szybciej niż standardowy WP).
  • Genialny edytor Markdown & Kart: Czysty interfejs pisarski, wklejanie kodu z kolorowaniem składni.
  • Wbudowane członkostwo (Memberships): Płatne subskrypcje, newslettery mailingowe z pudełka.

Ghost jako czysty Headless CMS:

Ghost posiada fantastyczne, doskonale udokumentowane Content API.

// Pobranie postów z Ghosta w czystym JS / Astro:
import GhostContentAPI from '@tryghost/content-api';

const api = new GhostContentAPI({
  url: 'https://moj-blog.ghost.io',
  key: '22444f78447824223ce6a7c059',
  version: "v5.0"
});

// Pobieramy 5 najnowszych wpisów jako JSON:
const posts = await api.posts.browse({
  limit: 5,
  include: 'tags,authors'
});

Przyszłość webu

Astro: Architektura Wysp (Islands) i Zero JavaScript

Co jeśli nie chcemy bazy danych ani ciężkiego CMS-a, ale zależy nam na komponentach i maksymalnym SEO?

Filozofia frameworka Astro:

  • Zero JS by Default: Astro kompiluje Twój kod do czystego HTML i CSS. Przeglądarka nie pobiera zbędnych megabajtów runtime'u.
  • Architektura Wysp (Islands Architecture): Tylko te elementy, które rzeczywiście są interaktywne (np. koszyk, karuzela), ładują odrobinę JavaScriptu.
  • Elastyczność komponentów: Możesz pisać komponenty w React, Vue, Svelte lub czystym Astro w jednym projekcie!
  • Doskonała współpraca z Markdown i CMS: Idealny frontend dla headless WordPressa lub Ghosta.
---
// Kod wykonuje się wyłącznie na serwerze podczas budowy!
import MyNavbar from '../components/Navbar.astro';
import InteractiveCounter from '../components/Counter.jsx';
const title = "Mój Nowoczesny Portal 2026";
---

<html lang="pl">
  <head>
    <title>{title}</title>
  </head>
  <body>
    <!-- 100% czysty statyczny HTML bez JS -->
    <MyNavbar />
    
    <main>
      <h1>{title}</h1>
      
      <!-- Tylko ten komponent ładuje JS w przeglądarce! -->
      <InteractiveCounter client:visible />
    </main>
  </body>
</html>
Krótki wgląd w backend

Mini Backend: Django & FastAPI jako API dla WWW

W tym semestrze skupiamy się na tworzeniu stron i CMS, ale poświęcimy 1-2 wykłady na zasilanie stron własnym API.

Django REST Framework

  • Podejście "Batteries Included" (pełen zestaw baterii).
  • Wbudowany panel administratora do zarządzania bazą danych (modele ORM).
  • Świetny, gdy potrzebujesz szybko stworzyć bazę produktów, artykułów czy rezerwacji i wystawić ją dla frontendu w formacie JSON.

FastAPI (Nowoczesny standard)

  • Asynchroniczny (ASGI), niesamowicie wydajny w Pythonie 3.12+.
  • Automatyczna dokumentacja interaktywna Swagger / OpenAPI pod adresem /docs.
  • Idealny do mikroserwisów, formularzy kontaktowych z wysyłką powiadomień, czy integracji AI z Twoją stroną WWW.
Frontend pobiera dane za pomocą natywnego fetch('https://api.strona.pl/produkty') i renderuje je w estetyczny interfejs.
